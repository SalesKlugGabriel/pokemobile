### 1. OBJETIVO

Criar no Blender um personagem humano adolescente masculino, aproximadamente 13–16 anos, explorador/treinador.

Direção visual:

- 3D low-poly estilizado;
- NÃO pixel art;
- NÃO chibi;
- NÃO realista;
- visual semelhante à concept art fornecida;
- geometria facetada/clean;
- formas simples mas intencionais;
- silhueta facilmente reconhecível à distância;
- adequado ao mundo 3D atual.

O personagem deve parecer adolescente, não criança pequena e não adulto.

Proporção aproximada: 6 a 6,5 cabeças de altura.

Altura de referência dentro do mundo: ~1,60 m.

A escala precisa ser configurada corretamente no Blender/Godot: 1 Blender Unit = 1 metro.

### 2. DESIGN

**PERSONAGEM:** adolescente; corpo magro/atlético; pernas relativamente longas; braços proporcionais; cabeça moderadamente estilizada; mãos e pés ligeiramente exagerados para leitura visual.

**CABELO:** castanho muito escuro/preto; estilizado; mechas grandes; evitar fios individuais; visível abaixo do boné; silhueta semelhante à referência.

**BONÉ:** vermelho; painel frontal claro; aba vermelha; NÃO utilizar logotipos/marcas protegidas; usar símbolo original simples do nosso universo.

**ROUPA:**
- Camada interna: camiseta clara/branca.
- Camada externa: jaqueta azul de exploração; aberta na frente; gola ligeiramente elevada; mangas parcialmente dobradas.
- Calça: cargo; cinza/preto; bolsos laterais; adequada para caminhada/exploração.
- Luvas: pretas; sem dedos; pequeno detalhe vermelho.
- Calçado: mistura entre trail running e hiking; vermelho/preto/branco; sola mais espessa; silhueta claramente esportiva.

**MOCHILA:** elemento visual importante. Compacta de exploração; preto/cinza escuro; detalhes vermelhos; alças visíveis; compartimento principal; compartimento frontal; pequenos bolsos laterais; possibilidade futura de anexar equipamentos. A mochila NÃO deve parecer fundida ao corpo.

### 4. MODELAGEM

Não criar o personagem como um conjunto de cubos/primitivas mal acabadas.

Mesmo sendo low-poly, a anatomia deve possuir: ombros; cotovelos; joelhos; quadril; pescoço; mandíbula; nariz simplificado; mãos reconhecíveis; pés/calçados definidos.

Evitar: braços cilíndricos retos; pernas em bloco; cabeça cúbica; mochila cúbica; roupas simplesmente pintadas sobre o corpo.

As roupas precisam possuir volume próprio.

Meta inicial: aproximadamente 8k–15k triângulos para o personagem completo. Não é necessário atingir exatamente esse número. **Qualidade visual > número arbitrário de polígonos.**

### 5. TOPOLOGIA

O modelo precisa ser ANIMÁVEL.

Atenção especial a edge loops em: ombro; cotovelo; punho; quadril; joelho; tornozelo; pescoço.

Evitar geometria que colapse durante deformação. Aplicar transforms corretamente antes do rig final.

### 6. MATERIAIS

Priorizar materiais simples e baratos. Não realismo PBR pesado.

Utilizar: Base Color; Roughness; poucos materiais; texturas pequenas quando necessárias.

Preferência: 512x512 ou 1024x1024 no máximo. Se possível, texture atlas.

Objetivo: baixo custo de renderização + linguagem visual consistente.

### 7. ROSTO

Simples. Elementos: olhos grandes, mas não anime/chibi exagerado; sobrancelhas; nariz estilizado; boca simples; mandíbula juvenil.

Não usar geometria facial excessivamente complexa.

Precisamos conseguir posteriormente representar: NORMAL · HAPPY · ANGRY/DETERMINED · SURPRISED · HURT.

Para V1, preparar estrutura que permita isso posteriormente. Não é necessário implementar sistema facial completo agora se prejudicar o MVP.

### 8. RIG

Criar armature humano reutilizável.

```
root
pelvis
spine_01 · spine_02 · chest · neck · head
clavicle_L · upperarm_L · lowerarm_L · hand_L
clavicle_R · upperarm_R · lowerarm_R · hand_R
thigh_L · shin_L · foot_L · toe_L
thigh_R · shin_R · foot_R · toe_R
```

Adicionar bones apropriados para mochila e boné, se necessário. Nomenclatura consistente. Preparar para reutilização das animações em NPCs humanos futuros.

### 9. SKINNING

Criar weights adequados. Validar obrigatoriamente: braço levantado; braço para frente; joelho dobrado; corrida; rotação de torso; cabeça; mochila.

Evitar clipping grosseiro entre: braço ↔ torso · braço ↔ mochila · perna ↔ roupa · cabeça ↔ boné · cabelo ↔ boné.

### 10. ANIMAÇÕES MVP

Depois que o modelo estiver aprovado **estruturalmente**: IDLE, WALK, RUN. **Somente essas três inicialmente.**

Não desperdiçar tempo criando dezenas de animações antes da validação visual.

- IDLE: respiração/movimento corporal muito leve.
- WALK: caminhada natural de adolescente.
- RUN: corrida esportiva/exploração.

Loop correto. Preferencialmente: idle ~2–4 s · walk ~1 s · run ~0,6–0,8 s.

Não usar root motion inicialmente, salvo se a arquitetura atual do jogo exigir.

### 11. BLENDER HEADLESS

A VPS não possui GPU dedicada. O pipeline headless existente já demonstrou que **Workbench é extremamente mais rápido que EEVEE** nessa máquina.

**NÃO usar EEVEE/Cycles para validações automáticas.** Utilizar Workbench/headless para previews. Não alterar essa decisão sem benchmark comprovando benefício.

Renderizar automaticamente: `front`, `front_3_4`, `side`, `back_3_4`, `back` — e também `idle`, `walk`, `run` para validação.

### 12. SCRIPT / REPRODUTIBILIDADE

Não quero que o personagem exista apenas porque foi manipulado manualmente no Blender. A operação deve ser **AI-first**. Tudo que for razoavelmente possível deve ser reproduzível por script.

```
tools/blender/player/
    create_player.py
    rig_player.py
    materials_player.py
    validate_player.py
    export_player.py
```

Pode alterar a arquitetura se encontrar estrutura melhor já existente no projeto.

O objetivo é permitir `blender --background --python create_player.py` e gerar novamente o asset.

Se determinadas etapas não forem sensatas via script, **documentar explicitamente**.

### 19. REGRA MAIS IMPORTANTE

Não confunda **LOW-POLY** com **BAIXA QUALIDADE**.

Se uma etapa procedural estiver produzindo resultado visual ruim, **não continue adicionando sistemas em cima dela**. Pare, identifique o problema visual e corrija a base.
